### 今日工作简述
- 实施了一系列基于用户反馈的性能优化、排版增强与邮件通知功能，系统进入稳定化阶段。
- 建立了全局并发控制与自愈重试逻辑，显著缓解了高并发场景下的资源竞争与 API 限流压力。

### 具体工作内容
- **邮件通知闭环**：基于 `smtplib` 建立 `EmailService` 并对接 SpaceMail SMTP 服务，实现任务完成指令的 HTML 动态邮件推送。
- **全域流控门控**：在 `services/agents/__init__.py` 建立全域 `asyncio.Semaphore(30)`，强制对所有并发任务的 LLM IO 执行流量削峰。
- **ArXiv 下载加速**：优化 `DownloadProgressCallback` 削弱了冗余的中断回调，同时在前端 `Dashboard.tsx` 引入 Shimmer 呼吸动画与交互式提示文案。
- **编译排版硬约束**：在后端 `utils.py` 实施字号（8-14pt）与行距（1.0-2.5）的 Bound Validation，防止无效参数破坏 LaTeX 布局。
- **代理执行并行化**：重构 `TranslatorAgent` 的 `execute` 模式，采用 `asyncio.gather` 对环境（envs）与标题（captions）执行阶段内并发请求。
- **Biblatex 韧性降级**：实现 `_fallback_biblatex_to_thebibliography` 逻辑，在缺少 `.bib` 源件时自动提取 `.bbl` 内容并构造原生引用模块。
- **重试算法演进**：将 LLM 请求的超时时间统一提升至 180s，并将重试策略由固定延迟升级为指数退避 (Exponential Backoff)。

### 问题与解决
- 问题：用户设置超大字号导致文档溢出，产生大量编译重叠错误。
  - 解决：后端引入边界强制修复提示并记录 `fmt_warnings`，前端设置 NumericField 输入限制。
  - 效果：有效地将用户排版自由限制在 LaTeX 核心支持的可视化区间内。
- 问题：访客模式下产生大量孤儿文件夹，占用服务器磁盘。
  - 解决：实现 `collect_orphaned_tasks()` 定期清理逻辑，自动擦除超过 `GUEST_TASK_TTL_HOURS` 的无数据库条目记录。
  - 效果：实现了存储资源的动态自治，极大降低了运维负担。

### 提升效果
- **吞吐能力**：通过翻译阶段并行化，中等规模论文的处理耗时降低了约 30%。
- **UX 体验**：全站提示框支持“点击即消失”与平滑动画，配合邮件通知，大幅缩短了用户对进度感知的空档期。

### 经验提炼
- 在资源受限的并发系统中，全局信号量（Global Semaphore）是比 per-task 限流更为可靠的防御手段。
- 处理遗留库（如 Biblatex）不兼容性时，解析生成的中间产物（BBL）往往比强行修复复杂的前导包配置（STY）更有效。
