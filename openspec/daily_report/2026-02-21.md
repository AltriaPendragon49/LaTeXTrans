### 今日工作简述
- 实现了基础的任务并发控制框架（TaskQueue）与访客模式资源清理机制。
- 落地了 arXiv 批量翻译与文件队列上传功能，大幅提升了多任务处理效率。

### 具体工作内容
- **并发调度控制器**：在 `task_manager.py` 中引入 `TaskQueue`，基于 `asyncio.Semaphore(3)` 实施全局并发硬限，并实现每用户 9 个活跃任务的额度追踪。
- **批量作业引擎**：开发 `POST /api/batch-translate` 端点，支持一次性动态提交最多 9 个 arXiv ID 或本地压缩包。
- **后台异步下载**：将 arXiv 源文件获取流程解耦为后台协程（`_download_and_enqueue`），使 API 端点实现秒级响应。
- **访客资源自治**：建立 `GuestTaskTracker` 映射表，配套每 30 分钟运行一次的定时清理任务（`GUEST_TASK_TTL_HOURS=2`），自动收割孤儿目录。
- **去重哈希纠偏**：修复本地上传翻译时的“哈希冲突”Bug，强制将 `source_path` 纳入配置摘要计算以防不同文件覆盖结果。
- **UX 看板升级**：新建 `BatchTranslation.tsx` 动态列表组件，实现多任务进度并行展示，并在预览页支持从 URL 直接恢复上下文。

### 问题与解决
- 问题：批量提交按钮由于 React State 闭包陈旧问题导致捕获到的任务列表为空。
  - 解决：重构 `BatchTranslation` 为 `forwardRef` 组件，采用 `useImperativeHandle` 暴露最新的提交函数引用。
  - 效果：彻底解决了复杂状态下异步提交逻辑失效的问题。
- 问题：上传大文件时 output reuse 判定过早导致前端未及时开启轮询。
  - 解决：在上传成功后提前手动触发一次 `pollTask`。
  - 效果：解决了复用命中时任务瞬间“丢失”在 UI 上的同步问题。

### 提升效果
- **系统健壮性**：通过并发控制杜绝了极端场景下的进程 OOM 或被 LLM Provider 封锁 API Key 的风险。
- **运维成本**：存储目录实现了“自动吐故纳新”，不再需要手动清理 `outputs/` 下的访客测试数据。

### 经验提炼
- 异步 API 的设计应遵循“提交即返回、状态可轮询”原则，防止长耗时下载或计算逻辑占用宝贵的 HTTP 连接池。
