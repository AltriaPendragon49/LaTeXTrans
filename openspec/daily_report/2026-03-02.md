### 今日工作简述
- 完善了多语言编译支持与 429 限流保护机制，建立了失败任务的隔离审查 (Quarantine) 流程。
- 显著增强了 LaTeX 编译前的结构修复与交叉引用还原能力，提升了系统在极端用例下的鲁棒性。

### 具体工作内容
- **API 快速失败策略**：在 `TranslatorAgent` 中显式捕获 4xx API 错误，终止无效循环；优先使用用户自定义 API 密钥。
- **一键式语言适配**：重构 `utils.py` 的 CJK 注入逻辑，实现 `ja`/`ko`/`zh` 与对应宏包（`luatexja`/`kotex`/`ctex`）的标准化 1-to-1 映射，并对西欧语言提供纯净透传。
- **全域限流保护**：在 LLM 调用中嵌套分级退避算法（Graduated Backoff），确保 `asyncio.sleep` 逻辑不持有全域信号量锁，防止并发死锁。
- **结构还原工具链**：在 `utils.py` 中新增 `restore_display_math_delimiters`、`restore_environment_structure` 和 `restore_label_commands` 等自动化纠偏工具。
- **任务隔离机制 (Quarantine)**：在 `TaskManager` 中拦截已确认失败的任务，将其资源迁移至 `data/failed_tasks` 并清理对应的生产环境记录。
- **语境感知分块翻译**：引入 `previous_context` 捕获机制，将上一个分块的结尾语境注入下一块的 System Prompt 中。
- **编译路径归一化**：规范化编译器的 `output_dir` 为绝对路径，并解决 LuaLaTeX 早期版本对 `\pdfoutput=1` 的评价 crash 缺陷。

### 问题与解决
- 问题：LLM 错误翻译或拼写 LaTeX 交叉引用标签 (`\label`)，导致生成 PDF 时链接失效。
  - 解决：引入 Label Key 自动化还原算法，通过模糊匹配将变体标签映射回原始。
  - 效果：大幅减少了编译过程中的 `undefined reference` 警告。
- 问题：前端在大规模错误发生时，SSE 轮询进入 404 死循环消耗资源。
  - 解决：在 `use-task-status-sse.ts` 中针对 404 状态实施主动 `cleanup()` 逻辑。
  - 效果：杜绝了前端无效连接对后端生成的额外压力。

### 提升效果
- **全球化能力**：攻克了法语、德语等西欧语言在 XeLaTeX 后备下的乱码问题，并在中日韩三语上实现了免配置直接编译。
- **可维护性**：通过 `failed_tasks` 隔离机制，构建了完善的“坏样本”沉淀与离线分析闭环。

### 经验提炼
- 即使是“自动纠错”也应保留足够的上下文：数学修复不应破坏显示模式，文本修复不应侵入数学模式。
- 在多租户环境中，任务失败不仅仅是一个状态，更是一个需要资源转移与快照保留的工程事件。
