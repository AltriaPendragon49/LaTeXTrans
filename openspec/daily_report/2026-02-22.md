### 今日工作简述
- 实现了深度定制的 LaTeX 排版（Typography）配置引擎，支持出版级的页面参数在线调整。
- 完成了认证系统的 OTP 数字验证码方案落地，并成功集成 Nvidia 专用 API 与模型名实时纠偏逻辑。

### 具体工作内容
- **高级排版引擎 (Typography)**：在 `utils.py` 实现 `apply_formatting_config()`，支持行间距弹性调节（setspace）、栏模式切换以及页边距（geometry）全量注入。
- **图表本地化支持**：实现对 Caption 指令集的自动化正则拦截，支持将图表、算法、表格说明自动汉化。
- **OTP 验证体系**：开发 8 位数字验证码认证流程，前端实现自定义单数字格子输入框，支持自动聚焦、粘贴以及移动端键盘适配。
- **Nvidia API 适配**：重写 `normalize_base_url` 助手函数解决 OpenAI 库对非标准 API 路径的兼容性问题，并落实 `qwen3` 系列模型的后端同步记录。
- **SMTP 基座集成**：完成 SpaceMail SMTP 服务器（`tomato@latextrans.online`）的离线对接，实现了用户注册确认邮件的稳定不依赖 VPN 下发。
- **持久化增强**：在 `translation_tasks` 表新增 `formatting` 独立 JSONB 列，并在翻译开始前通过 `update_task` 将语言元数据同步持久化。

### 问题与解决
- 问题：`\setCJKmainfont` 指令在注入时若位于 XeCJK 加载之前会导致编译报错。
  - 解决：新增 `_inject_after_cjk_package` 辅助函数，确保排版配置注入动作位于宏包加载的关键时序点之后。
  - 效果：解决了中文目标语言下自定义字体配置导致编译 100% 失败的严重兼容性问题。
- 问题：翻译历史记录无法真实还原任务执行时使用的具体 LLM 模型。
  - 解决：在 `run_translation` 流程中实时从响应中提取真实模型名，并调用持久化接口修正 `advanced_config` 快照。
  - 效果：实现了任务历史的可审计性。

### 提升效果
- **产品维度**：从传统的“单纯翻译”演进为“翻译 + 排版 + 通知”的一整套文献处理工作流。
- **UX 透明度**：前端增加 Nvidia 免费接口风险预警与可收起的 ArXiv 下载 Tip，显著提升了新手引导质量。
