# 项目背景

## 目的
LaTeXTrans-Pro 是一个基于检索增强生成（RAG）和多代理协作的 LaTeX 论文翻译系统。它旨在解决翻译 LaTeX 论文时出现的术语不一致、上下文丢失和编译错误等问题，确保翻译后的文档保持其格式并能正确编译为 PDF。

## 技术堆栈
- **后端：** Python 3.10+、FastAPI、LangChain
- **前端：** React 18+、TailwindCSS、Vite
- **数据库：** ChromaDB（术语向量数据库）、Redis（任务队列）
- **嵌入：** bge-m3
- **检索：** 混合（语义 + BM25）与交叉编码器重新排名
- **多模态：** Gemini-Vision（用于图像内容理解）
- **法学硕士：** Gemini 通过 LangChain（回退到 GPT）
- **LaTeX 引擎：** MiKTeX（通过 Docker，“即时安装”）

## 项目约定

### 代码风格
- 遵循Python PEP 8进行后端开发。
- 使用常规提交（例如，“壮举：添加碎布检索器”、“修复：解析器逻辑”）。
- 所有新功能都应包括单元测试。

### 架构模式
- **骨架优先：** 在填充复杂的子模块逻辑之前优先构建完整的端到端管道。
- **代理编排：** 使用LangChain代理（翻译器、编译器、CiteTool、ImageTool）来处理专门的任务。
- **RESTful API：** React 前端和 FastAPI 后端之间的通信。

### 测试策略
- AST 解析测试是强制性的，以确保 LaTeX 结构的完整性。
- 核心服务（解析器、RAG、代理）的单元测试。
- 手动验证已编译的 PDF 的格式一致性。

### Git 工作流程
- 标准分支策略（主/开发分支）。
- 遵循传统提交规范的强制提交消息。

## 域上下文
该项目涉及学术论文翻译和 LaTeX 文档处理领域。关键概念包括：
- **AST 解析：** 将 LaTeX 源代码转换为抽象语法树，以在保留结构的同时提取文本。
- **术语一致性：** 确保使用特定领域术语表一致翻译技术术语（例如“自我注意”）。
- **编译自我修复：**自动识别并修复由翻译或丢失包引起的 LaTeX 编译错误。

## 重要限制
- **AST 解析器：** 必须使用`pylatexenc`用于解析； LaTeX 结构处理严格禁止使用正则表达式。
- **Docker 隔离：** LaTeX 编译必须在使用 MiKTeX 的 Docker 隔离环境中进行。
- **RAG 驱动：** 翻译必须使用 RAG 检索的术语以避免模型幻觉。

## 外部依赖
- **LLM API：** Google Gemini（主要）、OpenAI GPT（后备）。
- **ArXiv API：** 由 CiteTool 用于获取上下文的论文摘要。
- **Docker Engine：** 运行 LaTeX 编译环境所需。
