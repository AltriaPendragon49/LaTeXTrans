## 添加的要求

### 要求：基于 Web 的用户界面
该系统应为 LaTeX 论文翻译提供一个基于浏览器的现代化界面，允许非技术用户在不具备 CLI 知识的情况下与翻译服务进行交互。

#### 场景：用户访问 Web 应用程序
- **鉴于**前端服务器正在 http://localhost:5173 运行
- **何时** 用户在现代浏览器中导航到 URL
- **然后** 主应用程序界面加载成功
- **AND** 界面显示“上传文件”和“arXiv ID”的选项卡选项
- **并且** 界面可跨桌面、平板电脑和移动设备屏幕尺寸进行响应

###需求：文件上传接口
系统应提供拖放文件上传机制`.tex`和`.zip`文件。

#### 场景：用户上传有效的 LaTeX 文件
- **GIVEN** 用户位于“上传文件”选项卡上
- **何时**用户拖动`.tex`文件到上传区
- **然后** 显示文件名和大小
- **并且**上传按钮变为活动状态
- **和**点击上传会触发后端`/upload`应用程序编程接口
- **并且**接收并存储任务 ID

#### 场景：用户上传无效的文件格式
- **GIVEN** 用户位于“上传文件”选项卡上
- **何时** 用户尝试上传`.pdf`文件
- **然后** 显示验证错误消息
- **并且** 上传被阻止
- **并且**错误建议接受格式（`.tex`、`.zip`）

#### 场景：用户上传的文件超出大小限制
- **GIVEN** 用户选择大于 50MB 的文件
- **何时** 文件被添加到上传区域
- **然后** 显示尺寸限制错误
- **并且**上传按钮保持禁用状态

### 要求：arXiv 集成接口
系统应为 arXiv 论文 ID 提供文本输入，以验证格式并触发自动下载。

#### 场景：用户提交有效的 arXiv ID
- **GIVEN** 用户位于“arXiv ID”选项卡上
- **何时** 用户输入有效 ID（例如“2508.18791”）
- **并且**单击提交按钮
- **然后** 根据 arXiv ID 格式验证输入
- **和**后端`/arxiv`API 被调用
- **并且**接收并存储任务 ID
- **并且**下载期间会出现加载指示器

#### 场景：用户提交无效的 arXiv ID 格式
- **GIVEN** 用户输入无效格式（例如“abc123”）
- **何时** 用户尝试提交
- **然后** 显示格式验证错误
- **并且**提交按钮被禁用
- **AND** 错误消息显示预期的格式

### 要求：实时进度跟踪
系统应通过基于轮询的状态更新来显示实时翻译进度。

#### 场景：翻译过程中的进度更新
- **鉴于**翻译任务已开始
- **何时** 前端进行民意调查`/task/{taskId}`每 2 秒
- **然后** 进度条更新以反映当前百分比 (0-100%)
- **AND** 显示当前阶段（“解析”、“翻译”、“编译”）
- **和** 显示相关消息（例如，“处理第 3/10 节”）

#### 场景：翻译成功完成
- **鉴于**翻译正在进行中
- **何时** 后端返回状态“已完成”
- **然后** 进度条显示 100%
- **和** 轮询自动停止
- **和**下载按钮变得可见
- **并且** 显示成功消息

#### 场景：翻译失败并出现错误
- **鉴于**翻译正在进行中
- **何时** 后端返回状态“失败”并带有错误消息
- **然后** 投票停止
- **并且** 错误警报与错误消息一起显示
- **AND** 该界面允许用户开始新的翻译

###需求：文件下载接口
系统应在翻译成功后提供翻译后的 PDF 和源文件的下载按钮。

#### 场景：用户下载翻译后的 PDF
- **GIVEN** 翻译状态为“已完成”
- **何时** 用户单击“下载 PDF”按钮
- **然后** 前端调用 `/download/{taskId}/pdf`
- **并且**浏览器启动文件下载
- **并且** PDF 文件以描述性文件名保存

####场景：用户下载翻译后的源代码
- **GIVEN** 翻译状态为“已完成”
- **何时**用户单击“下载源”按钮
- **然后** 前端调用 `/download/{taskId}/source`
- **和** a`.zip`存档已下载
- **并且** 存档包含翻译后的内容`.tex`文件

### 要求：跨浏览器兼容性
系统应在现代网络浏览器上正常运行。

#### 场景：应用程序在 Chrome 中运行
- **GIVEN** 用户在 Chrome（最新版本）中访问该应用程序
- **何时**用户执行任何操作（上传、翻译、下载）
- **那么** 所有功能都可以正常工作，没有错误

#### 场景：应用程序在 Firefox 中运行
- **GIVEN** 用户在 Firefox（最新版本）中访问应用程序
- **何时**用户执行任何操作
- **那么** 所有功能都可以正常工作，没有错误

#### 场景：应用程序在 Edge 中运行
- **GIVEN** 用户访问 Edge 中的应用程序（最新版本）
- **何时**用户执行任何操作
- **那么** 所有功能都可以正常工作，没有错误

### 要求：错误处理和用户反馈
系统应针对所有故障情况提供清晰、用户友好的错误消息。

#### 场景：后端 API 无法访问
- **鉴于**后端服务器未运行
- **何时** 用户尝试任何需要 API 通信的操作
- **然后** 显示连接错误消息
- **并且** 该消息建议检查后端是否正在运行
- **并且** 接口仍然可用于重试

####场景：文件上传时网络超时
- **GIVEN** 用户发起文件上传
- **何时**网络连接中断
- **然后** 显示上传失败消息
- **并且**用户可以重试上传
- **AND** 接口返回就绪状态
