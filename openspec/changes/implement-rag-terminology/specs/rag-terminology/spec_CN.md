# 规范：RAG 术语管理

## 添加的要求

### 要求：三级 RAG 管道
系统必须实现用于术语检索的三阶段 RAG 管道：查询转换 → 混合检索 → 交叉编码器重新排序。
#### 场景：完整管道执行
给定一个需要翻译的 LaTeX 部分，
当系统准备翻译提示时，
那么系统必须：
1. 从 LaTeX 内容中提取纯文本和关键术语
2. 并行执行向量搜索和关键字搜索
3. 使用交叉编码器模型对结果重新排序
4. 将 Top-N 术语作为提示插入`<Glossary>`块

### 要求：混合检索（双路径）
检索术语时，系统必须并行执行向量相似性搜索（pgvector）和关键字/全文搜索（tsvector）。
#### 场景：语义匹配与精确匹配
假设查询文本包含“自监督对比学习”，
当执行混合检索时，
然后向量路径必须返回语义相似的术语（例如“对比学习”、“自监督预训练”）
并且关键字路径必须返回精确/短语匹配（例如，“自我监督学习”）
并且两个结果集必须被合并和去重。

### 要求：跨编码器重新排序
系统必须使用交叉编码器模型在注入之前对来自混合检索的合并候选术语进行重新排序。
#### 场景：过滤噪声
给定来自混合检索的 30 个候选术语，
当应用重新排名时，
然后系统必须仅选择前 N 个上下文最相关的术语（默认 N=10）
并且必须从提示中排除不相关的术语。

### 要求：通用模式增强
RAG 术语管道必须适用于所有转换模式（0、1、2、3），而不仅仅是模式 2。
#### 场景：模式 0 下的翻译
给定模式 0（标准翻译）下的翻译任务，
当翻译一个部分时，
然后系统必须通过 RAG 检索并注入相关术语，与其他模式相同。

### 要求：系统默认词汇表
系统必须提供一个默认术语库，其中填充了存储在 Supabase pgvector 中的标准学术术语。
#### 场景：没有用户术语表的翻译
给定一个翻译任务，
当没有提供用户词汇表时，
然后系统必须从系统默认词汇表中检索术语。

### 要求：用户自定义术语表优先级
用户必须能够定义自定义术语表，这些术语表在重新排名期间优先于系统默认术语表。
#### 场景：术语冲突
假设系统术语表和用户术语表都包含术语“Field”，
当用户术语定义为“域”，系统定义为“字段”时，
然后在重新排序后，系统必须在翻译中优先考虑用户定义的“域”。

### 要求：术语自动提取
系统必须在翻译过程中自动提取新术语的源-翻译对，并将其保存到数据库中以供管理员审核。
#### 场景：提取新术语
鉴于翻译的部分，
当翻译完成后，
然后系统必须提取新术语并将其插入 Supabase`glossary_terms`带有“status = 'pending_review'”的表。

### 要求：RAG 注射
系统必须使用 RAG 检索相关术语并将其注入翻译提示中。
#### 场景：根据上下文进行翻译
给定一个源文本块，
在准备LLM提示时，
然后系统必须从词汇表中检索匹配的术语并将它们包含在提示中。

### 要求：优雅降级
RAG 管道必须在不阻塞转换的情况下正常失败。
#### 场景：RAG 服务不可用
鉴于 NVIDIA NIM API 无法访问或返回错误，
当系统尝试检索术语时，
然后系统必须回退到现有的基于 CSV 的术语词典
并且翻译必须在没有 RAG 增强的情况下进行
并且必须记录警告。

### 要求：性能约束
RAG 管道不得显着降低转换速度。
#### 场景：延迟预算
给定一篇标准的 30 节论文，
当启用 RAG 术语检索时，
那么每个部分的总 RAG 开销必须低于 2 秒
整篇论文的总附加时间必须低于 60 秒。
