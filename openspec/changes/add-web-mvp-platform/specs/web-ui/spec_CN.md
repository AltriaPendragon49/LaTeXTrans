## 添加的要求

###需求：文件上传接口
系统应提供基于浏览器的界面来上传 LaTeX 源文件。

####场景：拖放文件上传
- **何时**用户拖动`.tex`或者`.zip`文件上传区域
- **然后** 该区域通过视觉反馈突出显示，接受放置，通过“POST /upload”上传文件，并显示返回的任务 ID

####场景：点击浏览文件上传
- **何时** 用户点击上传区域
- **然后** 文件选择器对话框打开，接受`.tex`和`.zip`文件、上传所选文件并转换到进度跟踪视图

#### 场景：UI 拒绝无效文件类型
- **何时** 用户尝试上传`.pdf`或不支持的文件类型
- **然后** UI 显示错误消息“仅支持 .tex 和 .zip 文件”而不进行 API 调用

####场景：上传进度指示
- **何时** 文件上传正在进行中（POST /上传）
- **然后** UI 显示上传百分比或微调器，直到收到任务 ID

### 要求：arXiv ID 输入接口
系统应提供一个用于输入 arXiv 论文 ID 以启动翻译的表格。

#### 场景：有效的 arXiv ID 提交
- **何时** 用户输入有效的 arXiv ID（例如“2508.18791”）并单击“翻译”
- **然后** UI 发送 `POST /arxiv`，接收任务 ID，并转换到进度跟踪视图

#### 场景：arXiv ID 格式验证
- **何时** 用户输入与 arXiv ID 模式不匹配的文本 (XXXX.XXXXX)
- **然后** UI 在提交之前显示内联验证错误“无效的 arXiv ID 格式（预期：XXXX.XXXXX）”

####场景：arXiv下载失败处理
- **何时** 后端返回错误“无法从 arXiv 下载”
- **然后** UI 显示用户友好的错误并带有重试按钮

### 需求：翻译进度显示
系统应通过视觉指示器和状态消息显示实时翻译进度。

#### 场景：进度条更新
- **何时** 通过 `GET /task/{task_id}` 每 2 秒轮询一次任务状态
- **然后** 进度条动画以反映当前百分比 (0-100%) 和阶段标签更新

#### 场景：阶段转换
- **何时** 任务从“解析”→“翻译”→“编译”转换
- **然后** UI 显示特定于阶段的图标和消息（例如，“🔍 解析 LaTeX 结构...”、“🌐 翻译文本...”、“📄 编译 PDF...”）

#### 场景：完成通知
- **何时** 任务状态更改为“已完成”
- **然后** UI 停止轮询，显示成功消息“✅ 翻译完成！”，并显示 PDF 下载按钮

#### 场景：完成并发出警告通知
- **何时** 任务状态更改为“completed_with_warnings”
- **然后** UI 停止轮询，显示警告消息“⚠️ 翻译已完成，但有编译警告”，显示“下载 PDF”和“下载源代码”按钮，并显示一个警告图标，指示编译不完美

####场景：编译失败通知
- **何时** 任务状态更改为“failed_compilation”
- **然后** UI 停止轮询，显示错误消息“❌ PDF 编译失败”，突出显示“下载源代码”按钮，并显示消息“下载翻译后的 LaTeX 源代码以进行手动编译”，并可选择显示“重试”按钮

#### 场景：一般错误通知
- **WHEN** 任务状态更改为“失败”（非编译错误）
- **然后** UI 停止轮询，显示来自后端的错误消息，并显示“重试”按钮

### 要求：下载操作界面
系统应提供按钮来下载已完成任务的翻译输出文件。

####场景：下载PDF（编译成功）
- **何时** 用户单击状态为“已完成”或“带有警告的已完成”任务的“下载 PDF”按钮
- **然后** 浏览器开始下载`GET /download/{task_id}/pdf`文件名为“{project_name}.pdf”

####场景：下载源码（翻译成功）
- **何时** 用户单击状态为“已完成”、“带有警告的完成”或“失败编译”的任务的“下载源代码”按钮
- **然后** 浏览器开始下载`GET /download/{task_id}/source`文件名为“{project_name}_translated.zip”

####场景：仅下载源码（编译失败）
- **何时** 任务状态为“failed_compilation”（没有可用的 PDF）
- **然后** 只有“下载源代码”按钮可见，并带有突出的样式和工具提示“PDF 编译失败。下载 LaTeX 源代码以进行手动编译。”

#### 场景：下载按钮在完成之前隐藏
- **何时** 任务状态为“待处理”或“处理中”
- **然后** 下载按钮不可见（由进度跟踪器取代）

### 要求：UI 布局和导航
系统应以直观的布局组织上传/输入方法和进度跟踪。

####场景：上传方式之间Tab切换
- **何时** 用户位于“上传文件”选项卡并单击“arXiv ID”选项卡
- **然后** 文件上传表单隐藏，arXiv 输入表单出现，无需重新加载页面

#### 场景：响应式设计
- **何时** 用户访问移动设备上的 UI 或调整浏览器窗口大小
- **然后** 布局适应屏幕尺寸（在窄屏幕上垂直堆叠面板）

#### 场景：辅助功能合规性
- **当**用户通过键盘（Tab、Enter）导航时
- **那么** 所有交互元素（上传区域、输入字段、按钮）都是可访问和可操作的

### 要求：视觉设计标准
系统应使用 TailwindCSS 样式呈现现代、专业的界面。

#### 场景：高级审美
- **何时** 用户首次加载应用程序
- **然后** UI 显示干净、现代的设计，具有和谐的颜色（不是纯 RGB 颜色）、平滑的渐变和微妙的阴影

#### 场景：交互式反馈
- **当**用户将鼠标悬停在按钮或可点击元素上时
- **那么**通过颜色变化、缩放或阴影效果提供视觉反馈

#### 场景：加载状态
- **何时** 任何异步操作正在进行（上传、API 调用）
- **然后** 显示适当的加载指示器（旋转器、骨架屏幕或进度条）
