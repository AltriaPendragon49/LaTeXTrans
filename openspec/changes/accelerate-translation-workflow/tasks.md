# Tasks: 加速 LaTeX 翻译工作流（受控修复版）

1. [ ] **引入阶段 0：结构变体检测机制**
   - 编写 `detect_structure_invariant(env)` 工具函数，用于检测未转义的 `$`、结构宏泄漏等标志。
   - 在翻译调度入口集成检测，将结果存入任务上下文。
2. [ ] **剥离无限重试逻辑**
   - 搜寻当前翻译管线中的 `while` 重试或无度数的递归重试逻辑，将其硬编码限制最大重试次数为 1。
   - 重构 HTTP 429 被动限流捕获逻辑，保证单个 env 如果两次请求均被限流（即等待过 1 次后仍失败），则直接引发特定 Exception 以便降级。
3. [ ] **实现阶段 2：单步受限 LLM 修复器 (Controlled Repairer)**
   - 开发专门用于结构修复的独立 Prompt，严格指导模型“仅整理格式与转义，绝不做自然语言翻译”。
   - 将其实现为一个 `attempt_controlled_repair(context)` 函数。
4. [ ] **实现阶段 3：确定性降级机制 (Deterministic Downgrade)**
   - 编写降级处理器，实现“原文直出”、“预置占位符 + 原始注释”的代码生成。
   - 确保从阶段 3 返回的节点文本必定不会引发后续编译树的奔溃。
5. [ ] **引入异步分发与并发隔离机制**
   - 修改主 Task Runner/Dispatcher，根据变体检测结果，对于“正常” env 使用 `asyncio.gather` 或任务池高并发执行。
   - 对于“不安全”的 env 进行收集后按照单线程/单协程的方式排队处理，防止引发请求风暴。
6. [ ] **添加明确输出追踪日志**
   - 在每个处理完成的 Env Node 上追加处理状态 Metadata（例如 `DOWNGRADED`, `REPAIRED`）。
   - 修复结果汇总统计系统，确保处理完单篇论文后能在终端或报告中看到“强行降级的块数”与“修复次数”。
7. [ ] **全链路集成与验证**
   - 编写特定含有复杂公式、错误格式宏的毁坏源文本（Fixtures）。
   - 验证单篇乱码论文的处理时间是否因切断无穷重试而取得数量级（如 5x）的提速。
   - 验证最终的 `.tex` 是否能跑通后续编译器。
