## 添加的要求

### 要求：文件上传处理
系统应通过 HTTP 上传接受 LaTeX 源文件进行翻译处理。

#### 场景：上传单个 .tex 文件
- **何时**用户上传`.tex`通过“POST /上传”文件
- **然后**系统生成一个唯一的任务ID，将文件存储在`data/uploads/{task_id}/`中，并返回`{task_id, status: "pending"}`

#### 场景：上传 .zip 存档
- **何时**用户上传`.zip`包含 LaTeX 源的文件
- **然后**系统将存档解压到`data/uploads/{task_id}/`, validates the presence of `.tex`文件，并返回任务 ID

#### 场景：无效文件类型被拒绝
- **何时**用户上传具有不受支持的扩展名的文件（不是`.tex`或“.zip”）
- **然后** 系统返回 HTTP 400 并显示错误消息“不支持的文件类型”

#### 场景：文件大小限制强制执行
- **何时**用户上传大于 50MB 的文件
- **然后** 系统返回 HTTP 413，并显示错误消息“文件太大（最大 50MB）”

### 要求：arXiv 源检索
当提供有效的 arXiv ID 时，系统应从 arXiv 下载 LaTeX 源文件。

#### 场景：提供有效的 arXiv ID
- **何时** 用户通过 `POST /arxiv` 提交 arXiv ID（例如“2508.18791”）
- **然后**系统下载`.tar.gz`source，将其提取到`data/uploads/{task_id}/`，并返回任务ID

#### 场景：无效的 arXiv ID 被拒绝
- **何时** 用户提交格式错误的 arXiv ID（例如“invalid-id”）
- **然后** 系统返回 HTTP 400 并显示错误消息“无效的 arXiv ID 格式”

#### 场景：arXiv 下载失败
- **何时** arXiv API 无法访问或论文 ID 不存在
- **然后** 系统返回 HTTP 502，并显示错误消息“无法从 arXiv 下载：{reason}”

### 要求：文件下载交付
系统应提供翻译后的输出文件以通过 HTTP 端点下载。

#### 场景：下载翻译后的 PDF
- **何时** 用户请求`GET /download/{task_id}/pdf`对于已完成的任务
- **然后** 系统使用“Content-Disposition：附件”传输 PDF 文件；文件名=“{project_name}.pdf”`

#### 场景：下载翻译后的源代码
- **何时** 用户请求`GET /download/{task_id}/source`对于已完成的任务
- **那么** 系统将所有内容打包`.tex`文件到一个`.zip`归档并使用适当的标头对其进行流式传输

#### 场景：未完成就下载
- **何时** 用户请求下载状态为“待处理”或“正在处理”的任务
- **然后** 系统返回 HTTP 409 并显示错误消息“翻译尚未完成”

####场景：下载不存在的任务
- **何时** 用户请求下载无效任务 ID
- **然后** 系统返回 HTTP 404，并显示错误消息“找不到任务”
