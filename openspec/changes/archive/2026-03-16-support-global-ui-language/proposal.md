# 提案：支持全局 UI 语言与前端 i18n 统一治理

## 背景
当前产品虽然支持多目标语言翻译，但前端界面长期存在以下工程问题：

- UI 文案存在硬编码与翻译词条混用
- 任务进度展示依赖后端自然语言 `message`，可维护性差
- 语言切换、可访问性文案、Toast 与基础组件文案未完全统一
- i18n 改造完成后仍需要确保 lint、build、test 与构建产物保持健康

## 目标
本变更将前端 UI 语言能力从“提供一个语言选择器”提升为“统一、可维护、可验证的全站 i18n 基础设施”，同时补齐必要的工程收尾：

- 支持 8 种全局 UI 语言切换，并持久化用户偏好
- 前端主流程 UI 文案统一接入 i18n 词条
- 任务状态展示改为结构化字段驱动，不再依赖原始 `message` 文本解析
- 统一基础组件与 a11y 文案的本地化实现
- 完成 lint / test / build / pytest 校验，并控制构建噪音
- 在不改变功能行为的前提下，引入路由级懒加载和稳定分包，避免 i18n 改造造成首屏 bundle 回退

## 范围
### 包含
- 前端 `react-i18next` 基础设施与词条治理
- 多语言 locale 资源统一与异常字符修复
- Dashboard / Settings / History / Processing / Comparisons 等页面文案统一
- Sidebar / Sheet / LanguageSelector 等壳层与 a11y 文案本地化
- 后端任务状态结构化字段 `detail_code` / `detail_params`
- 路由级懒加载、构建分包与 CI 绿色验证

### 不包含
- 翻译质量优化
- 语言数量扩展
- 日志面板中原始诊断文本的翻译
