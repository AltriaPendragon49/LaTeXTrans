# Proposal: 修复 Nvidia API 配置及模型显示同步

## Problem
1. **Nvidia API URL 不兼容**：英伟达 API 的 `base_url` 结构与其他提供商不同，原有的自动追加 `/v1/chat/completions` 逻辑会导致 404 错误。且代码中直接使用了 `POST` 请求到 `base_url`，而非通过会自动拼接路径的 SDK。
2. **模型显示不一致**：前端显示的默认模型（`gpt-4.1-mini`）与后端配置（`qwen/qwen3-235b-a22b`）不一致；且翻译任务记录的是前端传入的配置名，而非后端实际调用的模型名。
3. **安全性隐患**：代码中存在硬编码的默认 API 密钥和测试回退逻辑，不利于环境变量管理。
4. **用户交互引导缺失**：ArXiv 官方下载耗时较长（占据 70% 以上时间），且默认使用的英伟达免费 API 在负载高时速度较慢，用户在等待过程中缺乏明确的延迟预期和 API 性能风险提示。

## Proposed Changes
1. **API URL 智能归一化**：实现 `normalize_base_url` 逻辑，识别已包含完整路径的 URL，并自动补全缺失路径，确保对 Nvidia 和自定义 API 的兼容性。
2. **实际模型回写同步**：在翻译任务启动阶段，将后端实际选用的 LLM 模型名回写到任务的 `advanced_config` 并更新数据库，确保翻译历史能准确反映所用模型。
3. **环境变量强制化**：更新环境变量配置，移除代码中的硬编码密钥和 `start.bat` 中的测试回退，确保所有敏感配置均通过 `.env` 管理。
4. **交互式引导增强**：在 Dashboard 增加显式的 ArXiv 下载耗时提示（Tip）及 Nvidia 免费 API 质量警告，并实现“点击即消失（Click-to-dismiss）”的轻量化交互，平衡信息展示与界面简洁度。

## Impact
- **可靠性**：解决 Nvidia API 调用的 404/403 错误。
- **一致性**：翻译历史记录将 100% 准确地显示翻译时使用的具体模型。
- **可维护性**：配置逻辑更清晰，易于支持更多异构 LLM API。
