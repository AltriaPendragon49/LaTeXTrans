# Design: Cloudflare Deployment Architecture

## Overview

本设计描述如何将 LaTeXTrans 系统部署为"前端托管 + 本地后端"的混合架构，实现零成本的外部访问能力。

## Design Decisions

### 1. 为什么选择 Cloudflare Pages + Tunnel？

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Cloudflare Pages + Tunnel** | 完全免费、无需公网IP、安全 | Tunnel 地址可能变化 |
| Vercel + ngrok | Vercel 免费、ngrok 易配置 | ngrok 免费版有限制 |
| 服务器部署 | 稳定、永久 | 需要付费 |

**决策**：选择 Cloudflare 方案，因为完全免费且生态统一。

### 2. 环境变量设计

```typescript
// 前端 API 地址配置
const API_BASE_URL = import.meta.env.VITE_API_URL || "http://localhost:8000/api"
```

使用 Vite 的 `import.meta.env` 机制，遵循 `VITE_` 前缀约定。

### 3. CORS 配置策略

后端需要允许以下来源：
- `http://localhost:*` - 本地开发
- `https://*.pages.dev` - Cloudflare Pages 默认域名
- 可选：自定义域名

## Trade-offs

| 决策 | 权衡 |
|------|------|
| 临时 Tunnel | 每次启动地址变化，但无需配置即可使用 |
| 前端重新构建 | API 地址变化时需重新部署，但保证类型安全 |
| 无持久化 | 简化部署，但后端重启后任务丢失 |

## Security Considerations

> [!WARNING]
> Tunnel 暴露本地后端存在安全风险：
> - 任何知道 Tunnel URL 的人都可以调用 API
> - 建议仅在测试期间启用

**缓解措施**：
1. 使用临时 Tunnel（URL 随机生成）
2. 测试完成后立即关闭 Tunnel
3. 后续版本可添加 API Key 验证

## Future Considerations

1. **固定 Tunnel 域名**：使用 Cloudflare Zero Trust 配置永久子域名
2. **完整云部署**：将后端部署到 Cloudflare Workers 或其他云服务
3. **API 认证**：添加 Bearer Token 保护 API 端点
