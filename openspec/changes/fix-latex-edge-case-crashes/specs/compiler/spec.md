# Capability: Compiler Resilience

## MODIFIED Requirements

### Requirement: Pre-Compilation Processing
- **Description:** The system MUST pre-process the LaTeX file to remove engine-specific incompatible primitives. Specifically, `\pdfoutput=1` MUST be stripped to prevent premature pages in `LuaLaTeX`, and a dummy `CJK` environment MUST be injected when targeting Chinese to prevent compilation crashes on documents using `xeCJK` alongside leftover `CJKutf8` commands.
#### Scenario: Handling Chinese documents with CJKutf8 and pdfoutput
- **Given** a translated Chinese paper containing `\usepackage{CJKutf8}` and `\pdfoutput=1`
- **When** the compiler pre-processes the document
- **Then** the system strips `\pdfoutput=1`, injects `\newenvironment{CJK}[2]{}{}`, and successfully compiles via XeLaTeX/LuaLaTeX without "undefined environment" errors or literal `=1` blank pages.

### Requirement: Auxiliary File Cleanup During Fallback
- **Description:** When the compilation loop falls back to secondary engines (e.g., from `xelatex` to `lualatex`), the system MUST delete engine-specific auxiliary state files (`.aux`, `.out`, `.toc`, etc.) generated by the previous engine to prevent cross-engine contamination (such as XeTeX-specific `\HyPL@Entry` tags breaking LuaLaTeX).
#### Scenario: Deleting XeLaTeX left-overs before LuaLaTeX fallback
- **Given** `xelatex` compilation fails and leaves behind an `.out` file containing `\HyPL@Entry{0<</S/D>>}`
- **When** the compiler falls back to `lualatex`
- **Then** the system deletes the `.out` file before running `lualatex`, ensuring LuaLaTeX does not print `0<</S/D>>` onto the final PDF.
