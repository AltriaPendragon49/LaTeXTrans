# 2026-04-13 公网链路修复与 PDF 阅读体验优化总记录

更新时间：2026-04-13

## 1. 文档目的

这份文档用于把本轮线上排查、架构调整、稳定性修复和后续 PDF 阅读体验修复一次性记录清楚，避免信息只散落在聊天记录和临时截图里。

这份文档覆盖两大部分：

1. 之前已经完成的公网链路不稳定修复与生产架构变更
2. 后续继续完成的首页 PDF 预览、详情页 PDF 加载、双栏阅读体验优化

## 2. 本轮之前的核心问题

在最早的线上排查中，主要暴露的是两类问题：

### 2.1 外网链路不稳定

表现包括：

- 外网访问偶发不通畅
- 前端页面能打开，但真实业务请求不稳定
- 后端公网入口链路不够稳，存在临时方案和历史残留配置

### 2.2 生产资产存储和预览路径不稳定

表现包括：

- 社区论文相关资产仍有一部分依赖服务器本地文件
- COS 已经引入，但并不是所有读取链路都完全稳定地围绕 COS 工作
- 译文 PDF 在浏览器 iframe 中的预览效果不稳定
- 详情页首屏和首页首屏存在明显慢加载问题

## 3. 之前已经完成的架构变更与稳定性修复

这一部分是本轮 PDF 优化之前，已经完成并上线的关键修复。

### 3.1 持久化存储改为 COS 为主

已完成：

- 生产环境社区资产以腾讯 COS 作为主存储
- 本地磁盘保留为运行期临时缓存和开发回退方案
- 上传到 COS 成功后，按既定策略清理临时本地文件
- 本地开发仍保留 `local_disk` 路径，兼容不接 COS 的本机调试场景

这意味着：

- 生产环境不再依赖“服务器硬盘长期保存社区资产”这条脆弱链路
- 社区资产的耐久性和迁移性更强

### 3.2 前端和后端公网访问链路重构

已完成：

- 前端继续保留在 Cloudflare Pages
- 前端统一走同源 `/api/*`
- Pages Functions 代理 `/api/*` 到稳定后端入口
- 后端公网入口不再依赖临时 Quick Tunnel
- 后端最终采用稳定的 Cloudflare Named Tunnel

最终公网入口变成：

- 前端：`https://latextrans.niutrans.com`
- 后端：`https://api.latextrans.online`

### 3.3 当前生产请求链路

现在的生产链路是：

1. 浏览器打开 `https://latextrans.niutrans.com`
2. 前端请求同源 `/api/*`
3. Cloudflare Pages Functions 转发到 `https://api.latextrans.online`
4. Cloudflare Named Tunnel 转发到腾讯云服务器 `82.156.76.218`
5. 服务器上的后端监听 `127.0.0.1:9001`

这次变更的意义是：

- 浏览器端不再暴露杂乱的历史后端地址
- 公网入口链路更稳定
- 后端迁移和重启对前端透明

### 3.4 COS 预览兼容性问题的修复

之前排查确认过一个关键事实：

- COS 默认域名下的 PDF 对浏览器 iframe 预览并不总是可靠
- 译文 PDF 即便在 COS 中存在，也可能因为响应头表现为下载而不是可靠内嵌预览

因此已完成修复：

- 译文 PDF 预览改为由第一方 API 代理输出 inline 响应
- 下载链路仍保留签名下载 URL

也就是说，现在：

- 浏览器预览走第一方 API
- 显式下载走签名下载

这样把“预览”和“下载”两条链路职责分开了。

### 3.5 结构化分析能力恢复

之前还修过一项明显回归：

- 社区论文的结构化分析内容曾退化为占位内容或缺失

已完成：

- 针对 `2508.18791` 的结构化分析重新生成并落库
- 详情页右侧结构化分析面板重新恢复为真实内容

### 3.6 生产 HTML 阅读模式策略调整

之前确认过：

- 公开 HTML 阅读路径是最慢的一条路径之一
- 但结构化分析又依赖预览 HTML 资产存在

因此已完成的策略是：

- 保留后台 HTML 预览资产生成
- 但在生产 UI 中禁用公开 HTML 阅读模式入口
- 这样既不影响结构化分析，又避免用户走最慢的阅读路径

## 4. 后续继续处理的 PDF 与阅读体验问题

在上面的架构稳定以后，又继续处理了下面这些偏阅读体验的问题：

1. 首页论文卡片 PDF 预览依然偏慢
2. 详情页英文原文 PDF 首屏加载偏慢
3. 详情页默认有时会过早进入译文 PDF 路径
4. 双栏模式下，希望保持原布局，不放大阅读区，只通过 PDF 打开参数尽量实现“整页可见”

## 5. 后续已完成的 PDF 体验优化

### 5.1 首页缩略图改轻

已完成：

- 保留首页卡片双缩略图展示方案，不改整体视觉结构
- 使用后端缩略图接口：
  - `GET /api/papers/{paper_id}/source-thumbnail`
  - `GET /api/papers/{paper_id}/translated-thumbnail`
- 调整缩略图生成逻辑，直接在 PDF 首页面栅格化阶段降低输出尺寸
- 升级缩略图缓存版本，强制线上重新生成轻量缓存

对样本文档 `2508.18791` 的实际复测结果：

- `source-thumbnail` 从约 `443860` bytes 降到约 `132552` bytes
- `translated-thumbnail` 从约 `551645` bytes 降到约 `147457` bytes

### 5.2 详情页英文 PDF 支持 Range 分段读取

已完成：

- 修复 `GET /api/papers/{paper_id}/source-pdf`
- 对本地文件直出分支补齐 `Range` 支持
- 浏览器发出字节区间请求时，接口现在返回 `206 Partial Content`

这意味着英文原文 PDF 不再总是整文件返回，首屏加载明显更合理。

### 5.3 默认阅读模式改回更稳的首开路径

已完成：

- 当前端只收到泛化的 `preferred_mode = translated` 时，不再直接首屏抢开译文 PDF
- 当公开 HTML 阅读模式不可用时，优先回到英文原文 PDF

这样避免用户首次进入详情页时就先拉较重的译文 PDF。

### 5.4 双栏模式只调 PDF 打开参数，不放大阅读区

按要求已完成：

- 没有改双栏布局宽度
- 没有扩大阅读区比例
- 仅调整 iframe 中 PDF 的默认打开参数

当前采用的参数为：

```text
#page=1&view=Fit&pagemode=none&toolbar=0&navpanes=0&scrollbar=0
```

目标是尽量让首次进入时更接近“整页可见”，同时不破坏原来的双栏布局。

## 6. 当前线上架构总结

截至本文档更新时，当前生产架构可以概括为：

### 6.1 前端

- 托管在 Cloudflare Pages
- 用户访问地址：`https://latextrans.niutrans.com`

### 6.2 后端

- 部署在腾讯云服务器 `82.156.76.218`
- 代码目录：`/srv/LaTexTrans`
- 服务：`latextrans-backend.service`
- 本地监听：`127.0.0.1:9001`

### 6.3 公网入口

- `api.latextrans.online`
- 通过 Cloudflare Named Tunnel 进入服务器

### 6.4 存储

- 生产主存储：腾讯 COS
- 本地磁盘：运行期临时缓存和开发回退

### 6.5 PDF 预览路径

- 英文原文 PDF：
  - 有直接可用源地址时优先走真实源地址
  - 本地直出场景支持 `Range`
- 中文译文 PDF：
  - 通过第一方 API 代理 inline 预览
  - 下载保持签名下载
