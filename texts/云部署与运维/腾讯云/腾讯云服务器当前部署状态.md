# 腾讯云服务器当前部署状态

更新时间：2026-04-13

## 1. 当前生产结论

当前正式生产环境已经稳定收敛到以下一套架构：

- 前端：Cloudflare Pages
- 前端正式地址：`https://latextrans.niutrans.com`
- 后端正式入口：`https://api.latextrans.online`
- 后端宿主服务器：受控生产主机（具体标识不再写入仓库文档）
- 服务器登录信息：仅保存在受控运维渠道
- 项目正式目录：以受控运维记录为准
- 后端服务：以受控运维记录为准
- 后端监听：`127.0.0.1:9001`
- 公网入口方式：Cloudflare Named Tunnel
- 生产主存储：腾讯 COS
- 本地磁盘角色：运行期临时缓存与开发回退

## 2. 当前公网访问链路

```text
浏览器
  -> https://latextrans.niutrans.com
  -> Cloudflare Pages
  -> Pages Functions 同源代理 /api/*
  -> https://api.latextrans.online
  -> Cloudflare Named Tunnel
  -> 受控生产主机
  -> 127.0.0.1:9001
  -> FastAPI
```

说明：

- 当前不再把“前端直接访问后端裸源站”作为正式方案
- 当前也不再使用临时 Quick Tunnel 作为正式公网入口
- 正式稳定方案是 Pages + Pages Functions + Named Tunnel

## 3. 当前服务器状态

### 3.1 项目目录

仓库文档不再记录生产主机的 SSH 地址、登录用户和落盘路径。实际值统一保存在受控运维记录中。

示意命令：

```bash
cd <project-root>
```

后续所有服务器操作都应以受控运维记录中的正式目录为准，不再依赖仓库内的明文主机资料。

### 3.2 后端服务

当前后端由 systemd 托管，服务名为：

```bash
<backend-service>
```

常用命令：

```bash
sudo systemctl status <backend-service> --no-pager
sudo systemctl restart <backend-service>
sudo journalctl -u <backend-service> -f
```

### 3.3 后端健康检查

服务器本机检查：

```bash
curl http://127.0.0.1:9001/api/health
```

公网入口检查：

```bash
curl https://api.latextrans.online/api/health
```

## 4. 当前存储架构

### 4.1 生产环境

当前生产环境采用：

```env
STORAGE_BACKEND_MODE=cos
```

含义：

- 社区论文相关持久化资产以 COS 为主
- 本地磁盘不再作为长期事实源

### 4.2 本地磁盘职责

当前本地磁盘只承担：

- 任务运行期输出
- COS 上传前的暂存目录
- 临时缓存
- 开发环境不接 COS 时的本地回退

### 4.3 当前社区资产路径策略

当前社区资产相关逻辑包括：

- `preview_html`
- `translated_pdf`
- `source_archive`

正式发布后以 COS 为准。

## 5. 当前 PDF 预览链路状态

### 5.1 英文原文 PDF

当前英文原文 PDF 已做过修复：

- 有可用真实源地址时优先直接使用源地址
- 本地文件直出场景支持 `Range`
- 浏览器对原文 PDF 的字节范围请求现在可以收到 `206 Partial Content`

### 5.2 中文译文 PDF

当前译文 PDF 预览链路为：

- 预览：第一方 API 代理 inline 输出
- 下载：签名下载 URL

这样是因为 COS 默认域名下的 PDF 并不能始终稳定满足 iframe 预览要求。

### 5.3 首页缩略图

首页 PDF 预览缩略图当前由后端提供：

- `GET /api/papers/{paper_id}/source-thumbnail`
- `GET /api/papers/{paper_id}/translated-thumbnail`

且已经做过轻量化处理。

## 6. 当前结构化分析状态

结构化分析功能当前已经恢复并可正常显示。

之前出现过的“结构化内容丢失/退化为占位文案”问题，已针对生产数据修复。

## 7. 当前代码同步方式

当前推荐的正式更新方式：

```bash
cd <project-root>
git pull origin main
sudo systemctl restart <backend-service>
```

更新后验证：

```bash
git rev-parse HEAD
sudo systemctl status <backend-service> --no-pager
curl http://127.0.0.1:9001/api/health
```

### 7.1 Token 池版本补充说明

如果当前部署的是 2026-04-18 开始接入的 Phase-1 系统 token 池版本，还应满足以下条件：

- 代码中实际存在 `backend/app/services/agents/llm_token_pool.py`
- 测试文件 `backend/tests/unit/test_system_llm_token_pool.py` 已纳入版本控制
- 服务器 `backend/.env` 已配置 `LLM_SYSTEM_POOL_GROUPS_JSON`
- 用户自带 `custom_api_key/custom_base_url` 仍走原有单 key 路径，不参与系统池轮换

部署后如后端启动失败，应优先检查：

```bash
cd <project-root>
git ls-files backend/app/services/agents/llm_token_pool.py
grep LLM_SYSTEM_POOL_GROUPS_JSON backend/.env
sudo journalctl -u <backend-service> -n 100 --no-pager
```
