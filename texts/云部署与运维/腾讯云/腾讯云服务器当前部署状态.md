# 腾讯云服务器当前部署状态

更新时间：2026-04-13

## 1. 当前生产结论

当前正式生产环境已经稳定收敛到以下一套架构：

- 前端：Cloudflare Pages
- 前端正式地址：`https://latextrans.niutrans.com`
- 后端正式入口：`https://api.latextrans.online`
- 后端宿主服务器：`82.156.76.218`
- 服务器登录用户：`ubuntu`
- 项目正式目录：`/srv/LaTexTrans`
- 后端服务：`latextrans-backend.service`
- 后端监听：`127.0.0.1:9001`
- 公网入口方式：Cloudflare Named Tunnel
- 生产主存储：腾讯 COS
- 本地磁盘角色：运行期临时缓存与开发回退

## 2. 当前公网访问链路

```text
浏览器
  -> https://latextrans.niutrans.com
  -> Cloudflare Pages
  -> Pages Functions 同源代理 /api/*
  -> https://api.latextrans.online
  -> Cloudflare Named Tunnel
  -> 82.156.76.218
  -> 127.0.0.1:9001
  -> FastAPI
```

说明：

- 当前不再把“前端直接访问后端裸源站”作为正式方案
- 当前也不再使用临时 Quick Tunnel 作为正式公网入口
- 正式稳定方案是 Pages + Pages Functions + Named Tunnel

## 3. 当前服务器状态

### 3.1 项目目录

正式目录：

```bash
/srv/LaTexTrans
```

后续所有操作统一以这个目录为准，不再使用旧文档里出现过的 `/srv/latextrans`。

### 3.2 后端服务

当前后端由 systemd 托管，服务名为：

```bash
latextrans-backend.service
```

常用命令：

```bash
sudo systemctl status latextrans-backend --no-pager
sudo systemctl restart latextrans-backend
sudo journalctl -u latextrans-backend -f
```

### 3.3 后端健康检查

服务器本机检查：

```bash
curl http://127.0.0.1:9001/api/health
```

公网入口检查：

```bash
curl https://api.latextrans.online/api/health
```

## 4. 当前存储架构

### 4.1 生产环境

当前生产环境采用：

```env
STORAGE_BACKEND_MODE=cos
```

含义：

- 社区论文相关持久化资产以 COS 为主
- 本地磁盘不再作为长期事实源

### 4.2 本地磁盘职责

当前本地磁盘只承担：

- 任务运行期输出
- COS 上传前的暂存目录
- 临时缓存
- 开发环境不接 COS 时的本地回退

### 4.3 当前社区资产路径策略

当前社区资产相关逻辑包括：

- `preview_html`
- `translated_pdf`
- `source_archive`

正式发布后以 COS 为准。

## 5. 当前 PDF 预览链路状态

### 5.1 英文原文 PDF

当前英文原文 PDF 已做过修复：

- 有可用真实源地址时优先直接使用源地址
- 本地文件直出场景支持 `Range`
- 浏览器对原文 PDF 的字节范围请求现在可以收到 `206 Partial Content`

### 5.2 中文译文 PDF

当前译文 PDF 预览链路为：

- 预览：第一方 API 代理 inline 输出
- 下载：签名下载 URL

这样是因为 COS 默认域名下的 PDF 并不能始终稳定满足 iframe 预览要求。

### 5.3 首页缩略图

首页 PDF 预览缩略图当前由后端提供：

- `GET /api/papers/{paper_id}/source-thumbnail`
- `GET /api/papers/{paper_id}/translated-thumbnail`

且已经做过轻量化处理。

## 6. 当前结构化分析状态

结构化分析功能当前已经恢复并可正常显示。

之前出现过的“结构化内容丢失/退化为占位文案”问题，已针对生产数据修复。
