# 2026-04-13 PDF加载与双栏阅读修复记录

更新时间：2026-04-13

## 1. 本轮处理的核心问题

本轮主要继续修复社区首页和论文详情页的阅读体验问题，重点包括：

1. 首页论文卡片 PDF 预览加载偏慢
2. 论文详情页英文原文 PDF 首屏加载偏慢
3. 论文详情页默认会过早进入译文 PDF 路径，导致首开体感偏慢
4. 双栏对照模式下，希望保持原有布局，不放大阅读区，只通过 PDF 打开参数尽量实现“整页可见”

## 2. 已完成的修复

### 2.1 首页预览缩略图改轻

- 保留首页双缩略图展示方案，不改卡片整体样式
- 后端继续提供：
  - `GET /api/papers/{paper_id}/source-thumbnail`
  - `GET /api/papers/{paper_id}/translated-thumbnail`
- 调整缩略图生成逻辑，直接在 PDF 首页面栅格化时降低输出宽度
- 升级缩略图缓存版本，强制线上重新生成更轻的缓存文件

实际复测中，目标论文 `2508.18791` 的缩略图体积从约：

- `source-thumbnail`: `443860` bytes
- `translated-thumbnail`: `551645` bytes

下降到约：

- `source-thumbnail`: `132552` bytes
- `translated-thumbnail`: `147457` bytes

### 2.2 详情页英文 PDF 支持 Range 分段读取

- 修复 `GET /api/papers/{paper_id}/source-pdf`
- 对本地文件直出分支补齐 `Range` 支持
- 浏览器请求字节区间时，接口现在可以返回 `206 Partial Content`

这意味着英文原文 PDF 不再总是走整文件返回，首屏可以更快进入可读状态。

### 2.3 详情页默认阅读模式改回更稳的首开路径

- 当后端只返回泛化的 `preferred_mode = translated` 时，前端不再直接首屏抢开译文 PDF
- 在生产环境下，如果公开 HTML 阅读模式不可用，则优先回到英文原文 PDF

这样可以避免首次进入详情页时先拉较重的译文 PDF 资源。

### 2.4 双栏模式只调 PDF 打开参数，不放大阅读区

- 没有改双栏布局宽度
- 没有强行扩大阅读面板比例
- 仅调整 iframe 中 PDF 的默认打开参数，使其更偏向整页适配

当前双栏 PDF 采用的打开参数为：

```text
#page=1&view=Fit&pagemode=none&toolbar=0&navpanes=0&scrollbar=0
```

目标是尽量让首次进入时更接近“整页可见”的体验，同时不破坏现有页面布局。
