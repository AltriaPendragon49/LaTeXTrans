# 云部署运维指南

更新时间：2026-04-13

## 1. 本指南用途

这份文档用于统一当前项目的生产部署、更新、验证和排障方式。

如果和更早的零散文档有冲突，以本指南和下列两份文档为准：

- `texts/云部署与运维/腾讯云/腾讯云服务器当前部署状态.md`

## 2. 当前正式生产架构

当前正式生产架构不是“单台服务器 + 本机 Nginx 直接对外暴露前端”，而是：

```text
前端
  -> Cloudflare Pages
  -> https://latextrans.niutrans.com

浏览器 API 请求
  -> 同源 /api/*
  -> Cloudflare Pages Functions
  -> https://api.latextrans.online
  -> Cloudflare Named Tunnel
  -> 82.156.76.218
  -> 127.0.0.1:9001
  -> FastAPI
```

## 3. 当前正式环境清单

### 3.1 前端

- 托管方式：Cloudflare Pages
- 正式域名：`https://latextrans.niutrans.com`

### 3.2 后端

- 宿主机：`82.156.76.218`
- 登录用户：`ubuntu`
- 项目目录：`/srv/LaTexTrans`
- 服务名：`latextrans-backend.service`
- 监听地址：`127.0.0.1:9001`

### 3.3 数据与存储

- 数据库：MySQL
- 生产主存储：腾讯 COS
- 本地磁盘：临时缓存、任务运行输出、开发回退

## 4. 当前正式更新流程

### 4.1 本地确认

先确认本地已经在最新主分支：

```bash
git checkout main
git pull origin main
git status --short
```

### 4.2 服务器更新

登录服务器：

```bash
ssh ubuntu@82.156.76.218
```

更新后端代码：

```bash
cd /srv/LaTexTrans
git checkout main
git pull origin main
```

重启后端：

```bash
sudo systemctl restart latextrans-backend
```

### 4.3 后端更新后验证

```bash
cd /srv/LaTexTrans
git rev-parse HEAD
sudo systemctl status latextrans-backend --no-pager
curl http://127.0.0.1:9001/api/health
curl https://api.latextrans.online/api/health
```

## 5. 当前前端发布流程

前端在本地发布到 Cloudflare Pages：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy-frontend.ps1
```

发布后建议检查：

- 首页是否能打开
- 详情页是否加载正常
- `/api/*` 请求是否仍然经由同源访问

## 6. 当前存储策略

### 6.1 生产环境

生产环境当前采用：

```env
STORAGE_BACKEND_MODE=cos
```

含义：

- 社区论文相关持久化资产以 COS 为准
- 本地磁盘只作为临时运行层

### 6.2 本地开发

本地开发允许使用：

```env
STORAGE_BACKEND_MODE=local_disk
```

这用于不接 COS 的本机开发和回归调试。

## 7. 当前 PDF 与阅读链路规则

### 7.1 英文原文 PDF

当前规则：

- 有真实源地址时优先直接使用真实 PDF 地址
- 本地文件直出路径支持 `Range`
- 浏览器可对原文 PDF 做分段读取

### 7.2 中文译文 PDF

当前规则：

- 预览走第一方 API inline 代理
- 下载走签名下载 URL

原因：

- COS 默认直链对 iframe 预览不够稳定

### 7.3 首页缩略图

当前首页 PDF 预览缩略图由后端统一生成并缓存，且已经过一轮轻量化优化。

## 8. 当前排障顺序

如果用户反馈“外网打不开”“详情页加载失败”“PDF 预览异常”，按下面顺序查：

### 8.1 先看本机后端

```bash
curl http://127.0.0.1:9001/api/health
```

### 8.2 再看公网后端入口

```bash
curl https://api.latextrans.online/api/health
```

### 8.3 再看前端正式站点

```bash
curl https://latextrans.niutrans.com
```

### 8.4 再看服务日志

```bash
sudo systemctl status latextrans-backend --no-pager
sudo journalctl -u latextrans-backend -f
```

### 8.5 如果是代码版本问题

检查本地、远端、服务器是否同一个提交：

```bash
git rev-parse HEAD
git rev-parse origin/main
```

服务器：

```bash
cd /srv/LaTexTrans
git rev-parse HEAD
git rev-parse origin/main
```
