# 基于检索增强与多智能体协作的 LaTeX 论文翻译系统 - 项目实施与演进计划 (v2)

> **最后更新**: 2026-02-21
> **项目状态**: MVP & 核心工程基建已完成 → 推进 RAG 与 LangGraph 多智能体阶段
> **项目架构**: FastAPI (后端) + React/Vite (前端) + PostgreSQL/Supabase (数据) + Redis/Celery (任务队列)

---

## 0. 项目总览与核心思路
本系统旨在建立一个高可用、高扩展性的 LaTeX 论文自动化翻译 Web 平台。
系统**已超额完成第一阶段**的并发处理、用户体系管控与编译环境增强。
当前的主要矛盾转移至 **AI 翻译视角的“智能化深化”**，核心目标是通过在翻译链路中嵌入 **词库级 RAG** 与构建基于 **LangGraph 的智能调度流**，解决传统 LLM 直译带来的术语跳脱、图文隔离和易编译崩溃等阻碍。

---

## 1. 已完成阶段：核心工程架构与 MVP (MVP & Infrastructure)

目前系统具备完善的基础环境生态能力，且远超预期地完成了大部分工程构建：
- **Web 基础交互**: FastAPI 提供后端 RESTful/WebSocket 通信，前端 React (TailwindCSS) 提供拖拽交互式视图。
- **核心翻译流与日志反馈**: 跑通了源文件(`.tex`/`.zip`)上传乃至 arXiv ID 云端在线拉取，具备精确剥离各编译周期的控制台级（Console-like）实时推送输出。
- **高并发与稳定调度**: 
  - 接入稳定任务队列分配机制（Task Queue），后台脱机翻译隔离调度。
  - 实现基于哈希与文档维度的 任务去重（Task Deduplication），防止重复消耗模型算力。
- **多用户系统与资源管控**: 
  - 闭环了从 Supabase 到客户端的实体访客账户路由。
  - 实现 Guest 受限模式及 定期资源空间沙盒清理（Guest Cleanup）。
- **进阶特性**: 支持了完整的 批量处理（Batch Translation）和用户持久化配置（Advanced Config）。
- **编译健壮性加强**: 隐去了 XeLaTeX 运行环境顽固疑难杂症（如附生第一页空白等）。

## 2. 待开发阶段 I：核心能力升级 —— 检索增强（RAG）模块

**目标**：彻底解决学术论文翻译由于 LLM 先验知识局限导致的“术语偏差、特定词汇意译失败”现象。

- **知识库底层选型**:
  - 引入 ChromaDB 等向量库构件引擎。
  - 定制具有强大双语学术词汇支持能力的 Embedding 向量化模型（例如 `bge-m3`）。
  - **词汇库管理机制**: 采用“全局官方词汇集 + 用户独立私有词库并存”。系统维护一套只读的官方学术词汇库，实体用户拥有独立的私有词汇集（可自定义上传和维护），并在实际检索与注入中享有更高优先级。
- **智能细粒度切分 (Intelligent Chunking)**:
  - 深度结合 `pylatexenc` AST 语法树骨架，不使用单纯粗暴的字数等比切分方案，而是按照章节（Section）、段落及宏包体等做语义级片段截出，提升单点文案内的知识保留完整度。
- **混合精度检索精排**:
  - 同步运作纯语义（Semantic Search）和 倒排精确字面匹配（BM25） 双模合并打分机制。
  - 在获取 TopK 时额外运行 Cross-Encoder 对初筛项作最精准二次重排（Reranker）。
- **动态 Prompt 上下文组装**:
  - 用截击注入的方式重构现有 Translator prompt，把检索出的学术映射作为带状变量填入如 `<Glossary>{retrieved_terms}</Glossary>` 中供给 LLM 进行精准用词锚定。

## 3. 待开发阶段 II：架构演进 —— 基于 LangGraph 的多智能体协作流

**目标**：扭转现状，解决由于上下文片段分离产生的语义断层，并通过在图网络流架构里引入自治智能体来处理报错阻断（Self-healing），打造一个非线性自动化调度方案。

- **LangGraph Workflow 改造**:
  - 完全替代之前的链式与独立代理，定义并生成包括 “拆解 -> 解析 -> 翻译 -> 审查 -> 编译” 为生命周期的条件分支图框架（State Graph），把现有的 ParserAgent 与 TranslatorAgent 平滑包装入内供全局接管。
  - **State 管理策略**: 采用“内存态执行（In-Memory State）”。LangGraph State 仅存在于单次任务执行期的 Worker 内存中，不做 Checkpoint 持久化且不接管 Supabase 的业务数据，任务失败即整体重跑。
- **引入专业生态动作工具 (Toolkit)**:
  - **`ImageTool`**: 识别捕获源文本里的插图引用环境（`\includegraphics{}`）并利用前端/云端的多模态模型（Gemini-Vision）解析图片内像素学术信息反馈给 LLM 以辅助正文对应词汇处理。
    *启停策略*：采用“用户可选的独立配置开关”，多模态特性作为高阶增强而非隐式行为，默认流程不触发视觉模型调用，以达到成本可控、路径可重现的工程收益。
  - **`CiteTool`**: 通过拦截并提取单行含被引用的段落（`\cite{xxx}`），在后台无感触发针对 arXiv / DOI 的论文库 API ，扒取当前被引文献的元数据与摘要文作为 LLM 特征提示补充项。
  - **`CompilerTool (Self-healing Loop)`**: 不再让编译致命错误直接停止流程丢给终端用户。当检测到 TeX 宏包出错/编译挂起，进入基于自我审查的试错图节点（最多设定 n 次），模型主动查阅编译日志 -> 自分析错误源 -> 改写生成修复后段落 -> 触发生命周期接驳。

> **说明**: 原计划考虑的双栏源码即时预览等高代价前端功能已在此阶段主动放弃，全面聚焦于 AI 链路的深度强化。

## 4. 待开发阶段 III：自动化测试与学术产出

**目标**：为 RAG 和智能体双轨优化落地提供科学数据支撑与定量比较结果。

- **构建标准对照数据集 Benchmark**:
  - 手工预处理与筛选收录来自诸如自然语言处理、计算机视觉、医学图像领域交叉点等高术语密度环境下的 10~20 篇高教标准论著集。
- **机器化评估与打分链**:
  - 开发独立自动化批量统计测算脚本计算双向 BLEU/ROUGE 指数，验证对纯字面的翻译挽救幅面变化；追踪含高频指定单词/专业词表下的术语一致性覆盖区间变化率。
- **系统分析指标输出设计**:
  - 在最终对照结果（消融实验集，Baseline 纯翻译 vs 检索加持与代理包网的综合翻译体系）输出 编译初次挽救通过比率、长文时停延展耗时比等技术维度数据。
